# 换背景 Prompt 模板库与案例

本文件存放经过实测的换背景完整 prompt 模板与复盘。SKILL.md 只放核心结构，需要具体背景类型或遇到新失败模式时读取本文件。

## 模板 A：场景图 → 浅灰台面（纯文字描述背景，无参考图）

适用：待编辑图是场景图/生活图，目标背景为浅灰棚拍台面，且用户没有提供背景参考图。

```text
对参考图执行背景替换：保留画面中[主体数量+逐项颜色/材质/饰物+姿态+相对位置]完全不变——造型轮廓、通透材质、光影方向全部保持不变。删除背景中的所有环境道具：[逐个点名，如木质桌面、浅米色墙面、陶瓷花瓶、尤加利叶、书籍]全部移除。将整个背景替换为干净统一的浅灰色纯色台面，专业产品棚拍风格，台面平整，光线均匀柔和，主体自然摆放于台面上，画面简洁无杂物。
```

**实测效果**：6 只玻璃猫全部保留、位置关系不变、背景干净无残留。

## 模板 B：场景图 → 浅灰台面（参考背景图驱动）

适用：用户提供了目标背景样式的参考图（如一张干净台面产品图）。`image_reference_url_list` 顺序 = [待编辑图, 背景参考图]。

```text
[img0]为待编辑的产品场景图，[img1]为背景样式参考图。保留[img0]中[主体数量+逐项颜色/材质/饰物+姿态+相对位置]完全不变：造型轮廓、玻璃质感、饰物、各自姿态与相对位置、光影方向全部保持。删除[img0]中的[逐个点名背景道具]等全部背景道具。参考[img1]中产品图的拍摄背景，将[img0]的背景整体替换为同款浅灰色纯色台面，台面平整、光线均匀柔和、无杂物，主体自然摆放于台面上。
```

**实测效果**：与模板 A 等效，6 只主体全部保留；多传一张参考图不会伤害保真度，但参考图若含产品会增大主体被干扰风险，此时优先用模板 A。

## 模板 C：任意图 → 纯白底

```text
对参考图执行背景替换：保留画面中[主体数量+颜色/材质/饰物+姿态]完全不变，造型轮廓、光影方向保持。删除背景中的所有道具与场景元素[逐个点名]。将背景替换为纯净白色，均匀柔光，无渐变、无杂物、无多余阴影，主体居中自然放置。
```

## 模板 D：任意图 → 指定场景背景（无参考图）

```text
对参考图执行背景替换：保留[主体]完全不变（数量、颜色、材质、饰物、姿态、相对位置、光影方向）。删除原有背景的全部环境元素[逐个点名]。将背景替换为：[台面材质+颜色，如原木色桌面]、[墙面/纵深颜色与质感]、[道具清单及摆放位置]、[光线氛围，如左侧自然光、柔和暖调]，主体自然融入场景，透视与主体一致。
```

## 模板 E：任意图 → 居家场景背景（参考背景图驱动）

适用：用户已生成/选中一张空场景背景图（如 Etsy 居家、ins/北欧/极简/宜家），要把产品图背景替换为该场景。`image_reference_url_list` 顺序 = [待编辑图, 背景图]。

```text
[img0]是待编辑的产品图，[img1]是目标背景参考图。保留[img0]中[主体数量+逐项颜色/材质/饰物+姿态+相对位置]完全不变：造型轮廓、通透材质、饰物、光影方向全部保持。删除[img0]背景中的[逐个点名，如白色圆形展示台、白色底座、纯白平面]。将[img0]的背景整体替换为[img1]的居家场景：[img1]的台面材质与颜色、墙面/纵深、光线氛围逐项写实]，台面焦点处自然摆放摆件，台面上不添加其他装饰物，画面干净。
```

**实测效果**：8 只/单只玻璃摆件全部保留，编织垫/窗台/水泥台三场景融合自然、无乱加道具。注意：`[img1]` 的空场景越干净（无摆件），越不容易被模型二次加道具。

## 背景方案生成要点（image_gen 文生图）

**默认硬约束（已实测确认，除非用户明确要求否则必须遵守）**：
- 背景**干净、无其他摆件**：不摆放花瓶/陶罐/干花/书本/雕塑等任何装饰道具；
- 商品**放桌面/台面上**：只生成台面/桌面/窗台等水平承载面场景，排除置物架、格柜、墙面挂架等非台面场景。

- 生成的是**空场景背景**（不放产品），比例与产品图一致（如 3:2 → 2048×1365），方便后续直接合成。
- prompt 固定三要素：台面材质与颜色（白橡木边几/原木窗台/浅灰水泥台面/亚麻桌布）、纵深与墙面（白墙/浅米色墙/窗外晨光）、光线氛围（自然光/暖光/冷调柔光）；加"台面完全空置，不摆放任何摆件/花瓶/陶罐/干花/书本等装饰"。
- 一次生成 4~6 张拉开差异（边几/格柜/桌布/编织垫/窗台/水泥台），拼带编号总览图给用户对话筛选。
- 对话筛选前先按默认硬约束预筛（非台面/带摆件的直接淘汰），再结合用户当次补充约束过滤。

## 多主体保护写法（关键）

单主体与多主体在 prompt 上唯一区别是保留项必须**逐只**描述：

- 差：`保持所有猫咪不变`（模型自由度太高，可能丢/改主体）
- 好：`保留画面中六只玻璃猫咪摆件完全不变：琥珀色、深酒红色、浅粉色、绿色、奶白色、烟灰色的通透玻璃质感，均带红色领结，各自姿态与相对位置不变`

数量词 + 逐项颜色 + 统一饰物 = 高保真的最低配置。

## 批量处理注意事项

- 批量时所有图沿用同一套 prompt 骨架（同一目标背景描述、同一保留项结构），只替换每张的主体枚举（数量/颜色/材质/饰物）。
- 文件夹含子文件夹（已分类）时，逐个子文件夹独立成批处理，结果回各自子文件夹。
- 图片平铺未分类时，先分组再处理：按文件名规律（连号/同系列/同日拍摄）+ Read 视觉特征（主体类型、颜色材质饰物、单/多主体）判断是否同一组商品；分组有歧义时先向用户确认。
- 分组后每组统一保留项（组共有的数量/颜色/材质/饰物/姿态）与目标背景；结果按组建子文件夹存放（用户要求平铺则例外）。
- 多主体图的数量核对：结果图裁剪 4 宫格（System.Drawing）逐格数，不依赖接口描述。
- 结果文件一律存回原图所在文件夹或对应分组子文件夹，命名 `<原名>_<目标背景短名>.png`，不覆盖原图。
- 单张失败记录后继续，不中断整批；结束时核对目录里每张输入图都有对应结果。

## 验证清单（每次必做）

1. 下载实际结果图（PowerShell：`curl.exe -L -o out.png "<url>"`，注意不要用 `curl` 别名）。
2. 用 Read 查看，人工核对：主体数量 == 原图数量；每个主体的颜色/饰物/姿态可辨识；背景纯净、无残留道具、无新增杂物。
3. 生成接口返回的 `Description` 可能数错数量（实测 6 只报成 5 只），**不要以返回描述判断结果，以实际图片为准**。
4. 有偏差时按 SKILL.md 的"常见失败与对策"表修改 prompt 重试。
